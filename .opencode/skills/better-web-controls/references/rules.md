# 交互规则与时机（rules）

> 这些题目的共同点：**先判断，再选工具**——判断内容关系、用户意图、后果轻重、等待时长。

## 提示消息 — 7个等级，从轻到重

判断口诀：**先想提示等级，再把样式告诉 AI**。打断程度要匹配信息的重要程度。

| 级别 | 名称 | 英文 | 何时用 | 特点 |
|---|---|---|---|---|
| 01 | 角标提示 | BADGE | 未读数·待办数·购物车件数 | 只标数字在图标右上角，瞄一眼就行 |
| 02 | 轻提示 | TOAST | 保存成功·复制成功·已收藏 | 右上角出现几秒自动消失，不打断 |
| 03 | 带操作的轻提示 | SNACKBAR | 删除后撤销·断线重试 | 轻提示附带可立即执行的按钮 |
| 04 | 跑马灯通知 | MARQUEE | 实时动态·活动播报·多条公告 | 固定顶部持续滚动，悬停暂停 |
| 05 | 消息中心通知 | NOTIFICATION | 导出完成·批量任务结果 | 发到消息中心留档，随时回看 |
| 06 | 警告提示 | ALERT | 权限不足·功能异常·风险 | 固定在内容区，处理前不消失 |
| 07 | 全局通知条 | BANNER | 系统维护·版本更新·全站活动 | 导航栏下方常驻，切换页面不消失，直到用户关闭 |

跟AI说模板：「用轻提示 Toast 告诉用户保存成功，右上角出现几秒自动消失」/「导出完成的提醒发到消息中心 Notification，不打断当前操作」。

## 二次确认 — 7种：打断程度匹配后果严重程度

三大价值：**减少误触 · 说明后果 · 留出反悔机会**。

1. **撤销 Undo**：事后撤销兜底，不打断操作；发消息、归档、可恢复删除
   「风险低可直接执行，页面上方提供明显的撤销入口」
2. **长按确认 Hold to Confirm**：按住一秒才执行，松手取消；防手滑、移动端危险按钮
3. **左滑删除 Swipe to Delete**：先滑出危险操作再点击；Web 列表、单项记录
4. **气泡确认 Popconfirm**：贴着按钮出现，不打断页面；中等风险单项操作
5. **弹窗确认 Modal**：黑色蒙版阻断，必须明确选择；删除重要文档等严重后果
6. **输入文字确认 Type to Confirm**：主动制造摩擦；删仓库、清空数据
   「只有输入 DELETE 后按钮才启用」
7. **勾选确认 Select All to Delete**（独立确认页）：后果逐条讲清、全部勾选才可执行；批量删除、最高风险

**决策线**：后果可逆→撤销；轻微风险→长按/左滑；中等→气泡；严重→弹窗；不可逆且影响大→输入确认或独立确认页。轻事重确认是骚扰，重事轻确认是灾难。

## 等待体验 — 6种 + 按长度决策

**等待不可怕，不确定才焦虑**。AI 的默认 = 孤零零的 Loading；好的等待 = 带步骤反馈。

1. **乐观更新 Optimistic Update**：先响应结果，后台同步；点赞、收藏、关注
2. **骨架屏 Skeleton Screen**：优先展示内容结构，原位渐现；列表、卡片、详情页
3. **懒加载 Lazy Loading**：滑到附近再加载；图片、长列表
4. **加载更多 Load More**：把节奏交给用户、记住位置；评论、搜索结果
5. **分段进度 Staged Progress**：说清当前做到哪步、还要多久；上传→解析→生成
6. **后台处理 Background Processing**：长任务转后台，任务中心随时查看；下载、导出、批处理

**按长度决策**：
| 长度 | 策略 |
|---|---|
| 短等待 | 先让结构出现（骨架屏） |
| 中等待 | 把过程说清楚（分段进度+进度动画，见 controls.md） |
| 长等待 | 允许离开（后台处理+完成提醒） |

## 表单校验时机

**校验别都堆在提交那一刻**——时机选错，用户填一整页才知道错在哪。
- **失焦校验 Blur Validation**：填完某项、光标离开立即检查；短表单、字段独立
- **提交校验 Submit Validation**：提交时统一检查、错误汇总标红、自动滚到第一个错项；长表单、字段有关联（如结束日期≥开始日期）
- 两者可混用；错误提示位置要说明：「错误提示显示在输入框下方」

模板：「手机号失焦时校验格式；提交时统一校验必填项；错误提示显示在输入框下方。」

## 表单整体体验 — 7个检查点

好表单**回答每一步的疑问**，不只是排列整齐。

1. **Label 字段标签**：输入框上方写清填什么，不能只靠 placeholder
2. **Required 必填标记**：提前标，别等提交才拦
3. **Helper Text 辅助说明**：复杂格式提前给示例（"11位手机号"）
4. **Inline Validation 即时校验**：填错后在字段旁说明原因
5. **Default Value 默认值**：告诉用户这里该填什么
6. **Logical Grouping 逻辑分组**：字段多时按个人信息/业务信息分区
7. **Success Feedback 成功反馈**：提交后明确结果+下一步动作

**可复制的完整 Prompt**：
「请优化这个表单的填写体验，不要只调整视觉。检查字段标签、必填标记、辅助说明、默认值、即时校验、错误提示和成功反馈；按填写顺序重新分组，并减少不必要的字段。每个错误提示都要说明"哪里错了"和"应该怎么改"。」

## 空状态 — 5种：不同原因，不同引导

**别把空状态都做成"提示＋按钮"**。先说清为什么空：
1. **首次使用 First-use**：给创建与导入入口，帮用户迈出第一步
2. **搜索无果 No Search Results**：保留原关键词，修改建议放搜索框旁，**不用加大按钮**
3. **筛选无果 No Filter Matches**：把当前条件留在页面、可逐个移除（"点击上方标签×，减少一个条件"）
4. **加载失败 Loading Error**：区分请求失败与真空数据，提供重试，已有内容先保留
5. **全部完成 All Done**：清单清零是好消息，给完成反馈即可

总结：创建给入口，搜索改关键词，筛选改条件，失败可重试，完成给反馈。

## 对齐 — 5种：哪个元素 · 跟谁对齐 · 按什么方式

别再说"排版整齐一点"。**内容区居中，不代表文字也要居中**——先确定参照系再选方式。
1. **左对齐 Left**：长段内容固定阅读起点；正文、产品说明
   「内容区保持居中，标题和正文共用左边线」
2. **居中对齐 Center**：图标、短标题、按钮一条轴；成功页、空状态引导
   「图标、短标题和按钮居中，详情信息左对齐」
3. **基线对齐 Baseline**：同行大字小字沿文字基线排列；价格"¥128 元/月"
   「金额和计费单位，沿同一条文字基线排列」
4. **两端对齐 Space between**：名称贴左状态贴右；订单列表、设置项
   「名称靠左，状态靠右，每行共用左右边线」
5. **数字对齐 Numeric alignment**：金额小数点数位上下对齐；报价表、财务报表
   「金额右对齐，统一小数位，使用等宽数字」

## 长页面定位 — 7种定位器

内容一多，用户不知道"我在哪、还能去哪"。**先判断用户意图，再选定位方式**。
1. **返回顶部 Back to Top**：长文章滚太深，一键回起点
2. **状态筛选 Status Filter**：活动、订单长列表
3. **锚点导航 Anchor Navigation**：内容有明确分组，快速定位；资源库、目录
4. **步骤导航 Stepper**：步骤状态与页面内容同步切换；注册、复杂表单
5. **折叠面板 Accordion**：按需展开细节，标题先当扫读线索；FAQ（不要一次全部展开）
6. **搜索 Search**：词条很多直接搜
7. **阅读进度 Reading Progress**：底部持续反馈读了多少还剩多远；文章、报告

## 分组方式 — 卡片不是默认答案

AI 有"万物皆卡片"的惰性。**先判断内容关系，再决定分组方式**：

| 关系 | 用什么 | 适合 |
|---|---|---|
| 上下承接 | 留白分区 | 介绍页、详情页、长文图 |
| 同一填写任务 | 表单分组 Form Sections | 注册、个人资料、团队设置 |
| 连续发生 | 列表 | 消息、记录、日志 |
| 整行同主题 | 通栏色块 Color Bands | 功能导航、专题区、行动区 |
| 并列比较 | 竖向分割线 | 套餐、方案对比 |

## 设计"黑话" — 7个词让页面立刻高级

说"做好看一点"AI 永远做不对；说这些词它秒懂：
1. **留白 Whitespace**：元素之间多留空，越舍得越高级
2. **栅格 Grid**：所有元素按一张隐形网格对齐，间距一致
3. **卡片+微交互 Card**：圆角小块，悬停轻轻浮起变色
4. **瀑布流 Masonry**：图片高低错落，不整齐反而耐看
5. **液态玻璃 Liquid Glass**：半透明磨砂+背景折射，苹果那种流动质感
6. **骨架屏 Skeleton**：加载时灰色占位，别让人干等
7. **空状态 Empty State**：列表为空配小图+一句引导，别留白板
