# 交互规则与时机（rules）

这类问题的共同处理方式：先判断，再选工具。判断依据包括内容关系、用户意图、后果轻重、等待时长。

## 提示消息 — 7个等级，从轻到重

判断口诀：先确定提示等级，再向 AI 说明样式。打断程度应与信息的重要程度匹配。

| 级别 | 名称 | 英文 | 何时用 | 特点 |
|---|---|---|---|---|
| 01 | 角标提示 | BADGE | 未读数、待办数、购物车件数 | 数字标在图标右上角，无需点击 |
| 02 | 轻提示 | TOAST | 保存成功、复制成功、已收藏 | 右上角出现数秒自动消失，不打断操作 |
| 03 | 带操作的轻提示 | SNACKBAR | 删除后撤销、断线重试 | 轻提示附带可立即执行的按钮 |
| 04 | 跑马灯通知 | MARQUEE | 实时动态、活动播报、多条公告 | 固定顶部持续滚动，悬停暂停 |
| 05 | 消息中心通知 | NOTIFICATION | 导出完成、批量任务结果 | 发到消息中心留档，随时回看 |
| 06 | 警告提示 | ALERT | 权限不足、功能异常、存在风险 | 固定在内容区，处理前不消失 |
| 07 | 全局通知条 | BANNER | 系统维护、版本更新、全站活动 | 导航栏下方常驻，切换页面不消失，直到用户关闭 |

表述模板：「用轻提示 Toast 告诉用户保存成功，右上角出现几秒自动消失」「导出完成的提醒发到消息中心 Notification，不打断当前操作」。

## 二次确认 — 7种：打断程度匹配后果严重程度

二次确认有三项价值：减少误触、说明后果、保留反悔机会。

1. **撤销 Undo**：操作后提供撤销入口，不打断操作。发消息、归档、可恢复删除
   「风险低可直接执行，页面上方提供明显的撤销入口」
2. **长按确认 Hold to Confirm**：按住一秒执行，中途松手取消。防误触、移动端危险按钮
3. **左滑删除 Swipe to Delete**：先滑出危险操作再点击。Web 列表、单项记录
4. **气泡确认 Popconfirm**：贴着按钮出现，不打断页面。中等风险的单项操作
5. **弹窗确认 Modal**：蒙版阻断页面，要求明确选择。删除重要文档等严重后果
6. **输入文字确认 Type to Confirm**：制造额外操作成本，阻止误操作。删除仓库、清空数据
   「只有输入 DELETE 后按钮才启用」
7. **勾选确认 Select All to Delete**（独立确认页）：后果逐条说明，全部勾选后执行。批量删除、最高风险

**决策线**：后果可逆用撤销；轻微风险用长按或左滑；中等风险用气泡；严重后果用弹窗；不可逆且影响大用输入确认或独立确认页。轻微事项采用重度确认会干扰用户，严重事项采用轻度确认会导致事故。

## 等待体验 — 6种，按时长决策

等待本身不产生焦虑，状态不确定才产生焦虑。AI 默认输出单独的 Loading；好的等待应提供步骤反馈。

1. **乐观更新 Optimistic Update**：先响应结果，后台完成同步。点赞、收藏、关注
2. **骨架屏 Skeleton Screen**：优先展示内容结构，内容原位渐现。列表、卡片、详情页
3. **懒加载 Lazy Loading**：滚动到附近再加载。图片、长列表
4. **加载更多 Load More**：浏览节奏交给用户，保留当前位置。评论、搜索结果
5. **分段进度 Staged Progress**：说明当前步骤与预计剩余时间。上传、解析、生成
6. **后台处理 Background Processing**：长任务转后台，任务中心随时查看。下载、导出、批处理

**按时长决策**：
| 长度 | 策略 |
|---|---|
| 短等待 | 先展示结构（骨架屏） |
| 中等待 | 说明过程（分段进度与进度动画，见 controls.md） |
| 长等待 | 允许离开（后台处理加完成提醒） |

## 表单校验时机

校验不应全部集中在提交时执行。时机不当会导致用户填完整页才知道错误位置。

- **失焦校验 Blur Validation**：某项填写完成、光标离开时立即检查。短表单、字段相互独立
- **提交校验 Submit Validation**：提交时统一检查，错误汇总标红，滚动定位到第一个错误项。长表单、字段存在关联（例如结束日期不早于开始日期）
- 两者可组合使用；需说明错误提示位置：「错误提示显示在输入框下方」

模板：「手机号失焦时校验格式；提交时统一校验必填项；错误提示显示在输入框下方。」

## 表单整体体验 — 7个检查点

可用的表单应回答填写过程中每一步的疑问，仅排列整齐不够。

1. **Label 字段标签**：输入框上方说明填写内容，不依赖 placeholder
2. **Required 必填标记**：提前标注必填项，不在提交时才拦截
3. **Helper Text 辅助说明**：复杂格式提前给出示例，例如"11位手机号"
4. **Inline Validation 即时校验**：填错后在字段旁说明原因
5. **Default Value 默认值**：说明该字段应填写的内容
6. **Logical Grouping 逻辑分组**：字段较多时按个人信息、业务信息分区
7. **Success Feedback 成功反馈**：提交后明确结果与下一步动作

**可直接使用的完整 Prompt**：
「请优化这个表单的填写体验，不要只调整视觉。检查字段标签、必填标记、辅助说明、默认值、即时校验、错误提示和成功反馈；按填写顺序重新分组，并减少不必要的字段。每个错误提示都要说明"哪里错了"和"应该怎么改"。」

## 空状态 — 5种：原因不同，引导不同

空状态不应统一做成"提示加按钮"。先说明页面为什么为空：

1. **首次使用 First-use**：提供创建与导入入口，帮助用户开始
2. **搜索无果 No Search Results**：保留原关键词，修改建议放在搜索框旁，不添加大按钮
3. **筛选无果 No Filter Matches**：当前条件保留在页面，可逐个移除（"点击上方标签×，减少一个条件"）
4. **加载失败 Loading Error**：区分请求失败与无数据，提供重试，已有内容先保留
5. **全部完成 All Done**：清单处理完毕属于正常结果，给出完成反馈即可

总结：创建给入口，搜索改关键词，筛选改条件，失败可重试，完成给反馈。

## 对齐 — 5种：哪个元素、跟谁对齐、按什么方式

不要用"排版整齐一点"这类表述。内容区居中不等于文字也居中；先确定参照系，再选择方式。

1. **左对齐 Left**：长段内容保持固定阅读起点。正文、产品说明
   「内容区保持居中，标题和正文共用左边线」
2. **居中对齐 Center**：图标、短标题、按钮沿同一轴线。成功页、空状态引导
   「图标、短标题和按钮居中，详情信息左对齐」
3. **基线对齐 Baseline**：同一行的大字与小字沿文字基线排列。价格"¥128 元/月"
   「金额和计费单位，沿同一条文字基线排列」
4. **两端对齐 Space between**：名称贴左、状态贴右。订单列表、设置项
   「名称靠左，状态靠右，每行共用左右边线」
5. **数字对齐 Numeric alignment**：金额的小数点与数位上下对齐。报价表、财务报表
   「金额右对齐，统一小数位，使用等宽数字」

## 长页面定位 — 7种定位器

内容较多时，用户需要知道当前位置与可用去向。先判断用户意图（浏览、返回、定位、完成任务），再选择定位方式。

1. **返回顶部 Back to Top**：长页面深度滚动后一键回到起点
2. **状态筛选 Status Filter**：活动、订单等长列表
3. **锚点导航 Anchor Navigation**：内容有明确分组时快速定位。资源库、目录
4. **步骤导航 Stepper**：步骤状态与页面内容同步切换。注册、复杂表单
5. **折叠面板 Accordion**：按需展开细节，标题作为扫读线索。FAQ（不要默认全部展开）
6. **搜索 Search**：词条数量多时提供搜索
7. **阅读进度 Reading Progress**：底部持续显示阅读位置与剩余内容。文章、报告

## 分组方式 — 卡片不是默认答案

AI 倾向于将所有内容装进卡片。应先判断内容关系，再确定分组方式：

| 关系 | 用什么 | 适合 |
|---|---|---|
| 上下承接 | 留白分区 | 介绍页、详情页、长文图 |
| 同一填写任务 | 表单分组 Form Sections | 注册、个人资料、团队设置 |
| 连续发生 | 列表 | 消息、记录、日志 |
| 整行同主题 | 通栏色块 Color Bands | 功能导航、专题区、行动区 |
| 并列比较 | 竖向分割线 | 套餐、方案对比 |

## 设计术语 — 7个词提升页面质感

"做好看一点"这类表述无法得到正确结果；以下术语 AI 可以直接理解：

1. **留白 Whitespace**：元素之间保留空隙，留白越充分质感越好
2. **栅格 Grid**：所有元素按同一张网格对齐，间距一致
3. **卡片+微交互 Card**：圆角容器，悬停时轻微浮起并变色
4. **瀑布流 Masonry**：图片高低错落排列，避免机械整齐
5. **液态玻璃 Liquid Glass**：半透明磨砂加背景折射，类似苹果系统的玻璃质感
6. **骨架屏 Skeleton**：加载时显示灰色占位，避免空白等待
7. **空状态 Empty State**：列表为空时显示小图与引导语，不留空白页
