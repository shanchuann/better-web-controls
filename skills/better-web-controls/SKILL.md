# Better Web Controls：模糊需求 → 准确描述

来源：Sue的AI知识库《web控件合集》35集方法论。核心洞察：**AI 做错页面，绝大多数时候不是能力问题，而是用户没说清"叫什么名字、什么形式、什么规则"**。本 Skill 的任务是在动手写代码之前，先帮用户把需求"翻译"准确。

## 语言规范

输出一律 **中文为主 + 英文术语**：控件先报中文名再括注英文名，如「胶囊按钮 PILL BUTTON」「鱼骨式步骤标签 CHEVRON STEPPER TABS」。这既是给用户看的选型说明，也直接用于最终 Prompt。

## 工作流

1. **识别需求类型**，路由到对应参考文件：
   | 用户想要 | 读 | 典型的话 |
   |---|---|---|
   | 新增/做一个控件 | `references/controls.md` | "做个下拉""加个按钮""轮播不止左右滑""做个弹窗" |
   | 页面/布局/结构 | `references/layouts.md` | "做个首页""登录页""导航栏""做AI产品""加个AI助手""做个悬浮球""大屏看板""工作台" |
   | 交互反馈/规则/时机 | `references/rules.md` | "提示怎么弹""删东西要不要确认""等待体验""表单什么时候校验""空状态" |
   | 修 Bug/页面不对劲 | `references/fixes.md` | "图片歪了""间距去不掉""被导航挡住""卡片不齐""弹窗太长" |
   | 数据图表 | `references/charts.md` | "做个报告""图表选型" |

   **「看板/大屏/报告」类请求涉及两个文件**：先读 `layouts.md`「大屏看板」定结构与布局，再读 `charts.md` 选图表——结构错比图表选错更致命。

2. **在候选中选型，并说出理由**。组件世界里极少只有一个答案：同一个"下拉"有 7 种（Select/Multi-select/Grouped/Cascader/Split Button/Mega Menu/Date Picker），同一个"进度"有确定/不确定两大类 8 种动画。给出 **2–3 个候选 + 每个的适用场景**，必要时反问用户关键判断依据（如：选项有没有上下级？后果是否可逆？能算出百分比吗？）。

3. **写选型笔记**：把候选对比、判断依据（反问了什么、用户怎么答的）、最终选型理由写入工作目录的 `notes.md`。这是交付物的一部分，便于用户复核与验收。

4. **输出完整 Prompt 或直接实现**，按各库的公式组装：中文名+英文名 → 使用场景/形式 → 操作规则。让用户直接可抄；若用户要求直接生成页面，按该 Prompt 的规格实现，产出单文件 HTML（除非用户另有要求）。

## 核心公式（所有选型的骨架）

- **组件描述三要素**：组件名称 · 使用场景 · 操作规则（"叫对名字，说清交互"）
- **判断先于选择**："X 远不止一种，先选对形式，再说清细节"——先判断内容关系/场景/意图，再报名字
- **强度匹配**：确认的打断程度要匹配后果严重程度（轻事重确认是骚扰，重事轻确认是灾难）；提示从轻到重 7 级
- **品类+形式**：进度=大类（确定/不确定）+ 动画形式，一次说清
- **四要素**：弹窗=类型→触发→关闭→内容；侧边栏=类型→位置→宽度→收起方式；Tab=场景→外形→选中态→切换反馈；轮播=形式→指示器→自动播放
- **Prompt 顺序**：大屏=业务关系→布局→视觉风格；页面=布局类型→背景/卡片/气质；按钮=形态→样式→文字

## 高频「跟AI说」句式模板

- 做控件：「做一个【中文名 英文名】。【形式】；【交互规则】；【边界情况】」
  例：「做一个可折叠侧边栏 Collapsible Sidebar：展开显示图标与文字，收起为图标栏，内容区域随比例伸缩；当前页面高亮。」
- 修 Bug：「【动词 + 具体参数】」——「改成填满容器 cover，别居中」「按文字基线对齐，不是按外框」「四周间距保持一致，都留 10px」
- 条件规则：「过去日期不可选，并显示住宿天数」「错误提示显示在输入框下方」「表格内部往下滚时，表头留在顶部」

## 完整示例（端到端）

用户：「帮我做个下拉，选择部门」

1. **判断**："下拉"远不止一种——先问内容关系：选项有没有层级？要不要多选？
2. **候选**（写入 `notes.md`）：
   - Select 单选下拉：部门固定几个、只选一个 → 最常见
   - Grouped Select：部门需按"研发/产品/运营"分组展示
   - Cascader：部门有上下级（公司→部门→小组），逐级选择
   - Multi-select：可同时选多个部门（数据过滤场景）
3. **判断问题**（用户在场时先问）：选项大概多少个？有没有上下级？可以多选吗？
4. **最终输出**（假设单选、无层级）：
   「做一个部门 Select 下拉：提供"产品部、研发部、设计部、运营部"四个固定选项，只能选择一个；选择后显示在触发框内，支持清空重选。」

## 使用提醒

- 用户需求模糊时（"高级一点""好看一点"），**先给判断问题或候选**，别直接写代码——"说'做好看一点'，AI 永远做不对"。
- 大坑对照：说"做个下拉"会得到最普通的那种；"做个轮播"只会得到左右滑+三个圆点；"做个侧边栏"会像十年前管理后台；"帮我做个高级的登录页"= 让 AI 瞎猜。凡遇这些词，先翻参考文件给出具体名字。
- 若用户有风格参考图，提醒：参考图要**连控件一起画/说**，只给色彩字体，AI 还是靠猜。
