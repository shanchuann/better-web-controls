# Better Web Controls：模糊需求到准确描述

AI 生成的页面不符合预期，多数情况并非模型能力不足，而是需求描述缺少控件名称、形式与操作规则。本技能的作用是在编写代码之前，先把模糊需求转写为准确描述。

## 语言规范

输出以中文为主，术语附英文。控件先报告中文名，再括注英文名，例如"胶囊按钮 PILL BUTTON""鱼骨式步骤标签 CHEVRON STEPPER TABS"。该表述用于选型说明，也用于最终 Prompt。

## 工作流

1. 识别需求类型，查阅对应参考文件：

   | 用户想要 | 参考文件 | 典型表述 |
   |---|---|---|
   | 新增控件 | `references/controls.md` | "做个下拉""加个按钮""做个弹窗" |
   | 页面布局与结构 | `references/layouts.md` | "做个首页""登录页""导航栏""做AI产品""大屏看板""工作台" |
   | 交互反馈规则与时机 | `references/rules.md` | "提示怎么弹""删除要不要确认""表单什么时候校验""空状态""支持暗色""适配手机" |
   | 修复页面问题 | `references/fixes.md` | "图片歪了""间距去不掉""被导航挡住""弹窗太长" |
   | 数据图表 | `references/charts.md` | "做个报告""图表选型" |

   涉及看板、大屏或报告的请求需要参考两个文件：先通过 `layouts.md` 的"大屏看板"一节确定结构与布局，再通过 `charts.md` 选择图表类型。结构错误的影响大于图表选型错误。

2. 列出候选并说明选型理由。同一类控件通常存在多种形式：例如"下拉"包含 7 种（Select、Multi-select、Grouped、Cascader、Split Button、Mega Menu、Date Picker）；"进度"分为确定与不确定两大类，共 8 种动画。输出 2 至 3 个候选及各自的适用场景；信息不足时向用户确认关键判断依据，例如选项是否存在上下级、操作后果是否可逆、能否计算百分比。

3. 记录选型笔记。将候选对比、判断依据和最终选型理由写入工作目录的 `notes.md`，作为交付物的一部分，便于复核与验收。

4. 输出完整 Prompt 或直接实现。Prompt 按固定顺序组装：控件中文名与英文名、使用场景或形式、操作规则。若用户要求直接生成页面，按该 Prompt 的规格实现，默认产出单文件 HTML。

## 核心公式

以下公式构成选型判断的基础。

- 组件描述三要素：组件名称、使用场景、操作规则。
- 判断先于选择：先判断内容关系、场景或意图，再确定控件名称。
- 强度匹配：确认交互的打断程度应与操作后果的严重程度匹配。轻微事项采用重度确认会干扰用户，严重事项采用轻度确认会导致事故。
- 品类加形式：进度描述为大类（确定或不确定）加动画形式，一次说清。
- 四要素描述：弹窗为类型、触发、关闭、内容；侧边栏为类型、位置、宽度、收起方式；Tab 为场景、外形、选中状态、切换反馈；轮播为形式、指示器、自动播放。
- Prompt 顺序：大屏为业务关系、布局、视觉风格；页面为布局类型、背景、卡片、气质；按钮为形态、样式、文字。

## 高频句式模板

- 新增控件："做一个【中文名 英文名】。【形式】；【交互规则】；【边界情况】"
  示例："做一个可折叠侧边栏 Collapsible Sidebar：展开显示图标与文字，收起为图标栏，内容区域随比例伸缩；当前页面高亮。"
- 修复问题：动词加具体参数。例如"改成填满容器 cover，不要居中""按文字基线对齐，不按外框""四周间距保持一致，均为 10px"。
- 条件规则："过去日期不可选，并显示住宿天数""错误提示显示在输入框下方""表格内部滚动时，表头保持在顶部"。

## 完整示例

用户需求："帮我做个下拉，选择部门"。

1. 判断：下拉存在多种形式，先确认内容关系，即选项是否有层级、是否需要多选。
2. 候选（写入 notes.md）：
   - Select 单选下拉：部门为固定少数选项，只选一个，最常见。
   - Grouped Select：部门需要按"研发、产品、运营"分组展示。
   - Cascader：部门存在上下级关系（公司、部门、小组），逐级选择。
   - Multi-select：可同时选择多个部门，适用于数据过滤场景。
3. 向用户确认：选项数量、是否存在上下级、是否允许多选。
4. 最终输出（以单选、无层级为例）：

   "做一个部门 Select 下拉：提供"产品部、研发部、设计部、运营部"四个固定选项，只能选择一个；选择后显示在触发框内，支持清空重选。"

## 使用注意

- 用户需求模糊（例如"高级一点""好看一点"）时，先给出判断问题或候选方案，不直接编写代码。仅凭"做好看一点"，AI 无法产出正确结果。
- 常见误区：说"做个下拉"会得到最普通的一种；说"做个轮播"通常得到左右滑动加三个圆点；说"做个侧边栏"通常得到样式陈旧的后台布局；说"做个高级的登录页"意味着 AI 只能猜测。遇到这类表述，先查阅参考文件给出具体名称。
- 用户提供风格参考图时，应说明参考图需要包含控件样式。仅提供色彩与字体时，AI 仍需猜测控件形式。
