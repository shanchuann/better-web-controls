# 删除项目确认交互 — 实现说明

## 场景
后台管理“删除项目”：删除会连带清掉 128 个任务、2.4 GB 文件，且不可恢复，属于典型的**不可逆高危操作**。

## 采用的确认方案
点击“删除项目”后弹出**模态确认弹窗**（而非浏览器原生 `confirm()`），核心设计点：

1. **明确后果**：弹窗用红色警示区逐条列出删除会造成的数据损失（任务数、文件体积、历史记录），用户在确认前能看清代价。
2. **输入名称确认（typed confirmation）**：必须手动输入项目名“官网改版 2024”，输入完全匹配后“永久删除”按钮才解锁，防止误点/手滑。这是不可逆删除的主流做法（GitHub 删除仓库同款模式）。
3. **危险按钮默认禁用**，输入匹配后才能点击；输入框内按回车可直接提交。
4. **取消路径友好**：Esc 键、点击遮罩空白、点“取消”均可安全退出，不做任何破坏性操作。

## 可访问性细节
- 弹窗使用 `role="dialog"` + `aria-modal` + `aria-labelledby/describedby`。
- 打开时自动聚焦输入框，Tab 键在弹窗内循环（焦点圈定），关闭后焦点归还给触发按钮。
- 删除结果用 `role="status"` 的 toast 反馈（“项目及其所有数据已删除”）。

## 视觉与反馈
- 红色系仅用于危险操作，与中性界面形成对比；图标 + 警示文案强化“危险”心智。
- 确认删除后卡片淡出移除，配合 toast 提示，操作闭环清晰。
