# 选型笔记：订单管理 · 负责人下拉与筛选

## 1. 需求类型识别

用户原文："订单管理页面里要选负责人，帮我做个下拉选择负责人，顺便按负责人筛选订单。"

- 需求类型：**新增控件**（下拉）+ **列表页筛选**（表格页面的过滤交互）。
- 查阅参考文件：`controls.md`（下拉组件 7 种、表格 5 种）、`rules.md`（空状态 5 种、对齐 5 种）、`layouts.md`（工作流实战：先定核心目标）。

## 2. 候选对比（下拉组件，共 7 种中筛出 3 个候选）

| 候选 | 中文名 / 英文名 | 适用场景 | 是否适配本需求 |
|---|---|---|---|
| A | Select 单选下拉 | 固定少量选项中选一个：订单状态、用户角色、负责人 | ✅ 负责人人数有限（团队规模内）、一次只按一个负责人筛选，最常见、认知成本最低 |
| B | Combobox 可搜索选择框 | 选项多、边搜边选 | 备选：若公司规模大、负责人超过约 20 人，应改用 Combobox |
| C | Multi-select 多选下拉 | 多选、选中项以标签展示，适合数据过滤 | 备选：仅当需要"同时按多个负责人筛订单"时选用 |
| ✗ | Cascader 级联选择 | 选项有上下级关系 | 不适用：负责人之间无层级，不是"部门→人员"的逐级选择 |

## 3. 关键判断依据

按 `controls.md` 下拉选型判断（日期→Date Picker；有上下级→Cascader；无层级有类别→Grouped；无层级少量→Select；多选→Multi-select）：

1. **选项是否存在层级**：负责人是平级人员列表，无上下级 → 排除 Cascader。
2. **是否需要多选**：需求说"按负责人筛选"（单数），未要求多负责人组合筛选 → 不选 Multi-select。
3. **选项数量**：默认按团队规模（≤ 10 人）处理，选 Select；若实际人数超过约 20 人，应升级为 Combobox（笔记中留有此判断线）。

## 4. 最终选型与理由

**最终选型：负责人 Select 单选下拉（可清空），用于订单列表的表头筛选 Column Filter。**

理由：
- 负责人为固定少量平级选项、单选场景，Select 是匹配度最高、认知成本最低的形式（controls.md 判断规则直接命中）。
- 筛选规则明确：默认"全部负责人"，选中后表格即时过滤，触发框内显示所选负责人，支持一键清空重选（对应高频句式"支持清空重选"）。
- 交互反馈遵循 `rules.md`：
  - 筛选无果时使用"筛选无果 No Filter Matches"空状态——保留当前条件，条件以可移除的标签呈现，并提供"清除筛选"按钮；
  - 金额列右对齐、等宽数字（对齐规则 05 数字对齐）；
  - 订单号与金额用 tabular-nums 保证数位对齐。
- 附带规则：筛选生效时在筛选栏显示条件标签（负责人 ×），点击 × 等同清空。

## 5. 实现规格（最终 Prompt）

> 做一个中文"订单管理"页面，核心是负责人 Select 单选下拉与订单筛选：
> 1. 筛选栏内做一个负责人 Select：选项为"全部负责人"+ 6 名固定负责人，只能选一个；选择后显示在触发框内，支持点击 × 清空重选；点选项或按 Esc / 点击外部关闭面板。
> 2. 订单表格按所选负责人即时过滤，显示"共 N 单 / 筛出 M 单"；筛选生效时显示条件标签，可单独移除。
> 3. 无匹配时展示"筛选无果"空状态：保留当前条件，提示减少条件并提供清除筛选按钮。
> 4. 表格含订单号、客户、负责人（徽章）、状态（徽章）、金额（右对齐等宽数字）、日期；浅色后台风格、卡片化、留白充足。

## 6. 复核提示（给验收者）

- 若实际负责人人数 > 20，请改用 Combobox（边搜边选）。
- 若需要"同时按多个负责人筛订单"，请改用 Multi-select（选中项显示为标签、可单独移除）。
