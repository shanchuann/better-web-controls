# 选型笔记 — CRM 客户列表两种空状态

需求类型：交互反馈 → 空状态（参考 `references/rules.md`“空状态 — 5种：原因不同，引导不同”；对齐方式参考同文件“对齐 — 5种”第 2 条：空状态引导采用居中对齐）。

## 需求判断

用户场景是 CRM 客户列表的两种"空"，**原因不同，引导必须不同**：

1. 新用户刚注册、还没有客户 → 属于“**首次使用 First-use**”。用户不知道下一步做什么，应提供创建与导入入口，帮助用户开始。
2. 搜索/筛选后没有匹配结果 → 属于“**搜索无果 No Search Results**”与“**筛选无果 No Filter Matches**”。列表本身有数据（或可能被关键词/条件过滤掉），问题出在条件上，应保留原关键词、当前条件留在页面并可逐个移除，**不添加大按钮**。

核心口诀：**创建给入口，搜索改关键词，筛选改条件。**

## 候选对比

### 状态一：新用户无客户

| 候选 | 描述 | 适用 | 结论 |
|---|---|---|---|
| A. 首次使用空状态 First-use Empty State | 居中插画 + 一句说明"为什么为空" + 主按钮"新增客户" + 次按钮"导入客户" | 用户第一次进入、列表确实没有任何数据 | ✅ 选用 |
| B. 引导任务清单 Onboarding Checklist | 以步骤清单（1 建客户 2 建商机 3 记跟进）代替列表 | 需要引导用户完成一串初始化动作的复杂产品 | 不选：CRM 新用户诉求明确（先有客户），清单反而增加认知负担，可作为后续迭代 |
| C. 仅一段提示文本 | 灰字"暂无数据" | 后台内部工具、低频页面 | 不选：没有任何行动入口，新用户会卡住，是典型反面做法 |

### 状态二：搜索/筛选无匹配结果

| 候选 | 描述 | 适用 | 结论 |
|---|---|---|---|
| A. 搜索无果型 No Search Results | 搜索框保留原关键词；说明文字 + 修改建议放在**搜索框旁/下方**（检查拼写、换更短关键词）；不放大按钮 | 仅有关键词、无筛选条件时无结果 | ✅ 选用（关键词场景） |
| B. 筛选无果型 No Filter Matches | 当前筛选条件保留在页面上方，每个条件是可单独移除的标签（点 × 减少一个条件），另提供"清除全部筛选"的文字链接（非大按钮） | 有筛选条件、被条件过滤到空 | ✅ 选用（条件场景） |
| C. 统一"暂无结果 + 返回按钮" | 一张通用空状态图加一个大按钮 | —— | 不选：违反"空状态不应统一做成提示加按钮"；大按钮会把"搜索无果"引向错误动作（如新建客户），且丢失"改关键词/减条件"的正确引导 |

用户原文把"搜索/筛选"并列为一种状态。判断依据：两者引导动作不同（改关键词 vs 减条件），但经常同时发生（既有关键词又有筛选条件）。因此实现为**一套容器、动态组合**：有关键词时显示关键词与搜索建议；有筛选条件时显示可逐个移除的条件标签；两者同时存在时同时呈现，各给各的出口。

## 最终选型规格（Prompt 组装：名称 + 场景/形式 + 操作规则）

1. **首次使用空状态 First-use Empty State**：用于新注册用户、客户数为 0 的客户列表。插画、标题"还没有客户"、说明文字、主按钮"新增客户"与次按钮"导入客户（Excel/CSV）"垂直居中排列；图标、短标题与按钮居中对齐。
2. **搜索无果 No Search Results**：用于关键词无匹配。搜索框内保留原关键词不清空；提示语"没有找到与 ×× 相关的客户"，下方给出 2–3 条修改建议（检查拼写、换更短的关键词、按公司名或手机号搜索）；提供"清除关键词"文字链接；不放置大按钮。
3. **筛选无果 No Filter Matches**：用于筛选条件把列表过滤为空。当前所有筛选条件以标签形式保留在提示区，每个标签可点 × 单独移除；提供"清除全部筛选"文字链接；同时存在搜索关键词时，一并显示搜索建议。

## 实现要点

- 单文件 HTML，中文，双击可直接打开；内嵌 CSS/JS。
- 为便于验收，页面带一个"演示视角"切换（仅供预览四种形态：新用户 / 搜索无果 / 筛选无果 / 有数据），业务代码本身依据数据与条件自动判定空状态类型。
- 判定优先级：客户数为 0 → First-use；列表有数据但过滤后为空 → 按存在关键词/条件组合显示 No Search Results / No Filter Matches。
