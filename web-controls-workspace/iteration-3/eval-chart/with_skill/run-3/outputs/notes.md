# 选型笔记：管理层月度经营报告页面

## 0. 工作流依据

用户需求属于“报告 / 看板”类，按 SKILL.md 工作流查阅两个参考文件：

1. `references/layouts.md` 的“大屏看板”一节 —— 先定结构与信息层级；
2. `references/charts.md` —— 再为每份数据选图表类型。

按参考文件强调的顺序：**先说清业务关系（这是给管理层看的复盘），再选布局，最后定视觉风格。结构错误的影响大于图表选型错误。**

## 1. 业务关系判断

- 受众：管理层，阅读目标是“先看结论 → 再看变化 → 最后定位原因”。
- 数据四项各自回答的问题：
  | 数据 | 回答的问题 | 层级 |
  |---|---|---|
  | 本月营收 480 万、环比 +12% | 结果怎么样 | 结果 |
  | 近 12 个月营收走势 | 变化趋势如何 | 趋势 |
  | 各产品线营收占比 | 收入构成从哪来 | 构成 |
  | 各渠道转化流失 | 增长/流失的原因在哪 | 原因 |
- 无实时监控、无异常告警诉求，是**经营复盘汇报**，不是态势大屏 → 排除“中心聚焦”“流程链路”类布局动机。

## 2. 布局候选对比（对应参考文件 5 种大屏布局中的 3 个候选）

| 候选 | 适用场景（参考文件原文） | 是否适配 |
|---|---|---|
| **02 上总下分 Summary First** | 经营复盘、汇报大屏、管理看板 | ✅ 完全一致 |
| 03 左右分栏 Overview & Detail | 区域对比、业务对比、异常诊断 | ⚠️ 本需求无“一格整体 / 一格明细”的对望关系，是层层往下钻，不是左右对照 |
| 04 网格模块 Modular Grid | 设备监控、综合态势等多种状态并巡 | ❌ 仅 4 类信息、无多状态监控需求，易堆成“图表拼盘” |

**最终选型：上总下分（Summary First）**，三层递进：

- 顶部（结果）：KPI 卡（每卡一个指标，标注环比）+“本期要点”结论条；
- 中部（趋势/构成/流程）：折线、环形、漏斗三张图并排；
- 底部（原因）：各渠道转化流失明细表（可定位到具体渠道与环节）。

## 3. 图表候选对比（charts.md 决策问句逐条走）

### 3.1 近 12 个月营收走势

判断问句：查看变化趋势？→ 折线（纯趋势）或面积（趋势加总量）。

| 候选 | 判断依据 |
|---|---|
| **折线图 Line Chart** | 月度营收是各期独立数值，重点是环比变化走势（本月 +12% 需一眼看出跃升） |
| 面积图 Area Chart | 适合“累计收入、累计注册量”等趋势加总量；此处非累计数据，面积填充无含义 |

**选折线图**，末点高亮标注“480 万”，直接承接顶部 KPI。

### 3.2 各产品线营收占比

判断问句：拆解占比？→ 饼图（不超过 5 类，单一构成）或堆叠柱状（类别内部构成）。

| 候选 | 判断依据 |
|---|---|
| **环形图（饼图变体）** | 4 个产品线 ≤ 5 类、单一构成、总量 480 万已知；中心可放总量，管理层读数友好 |
| 堆叠柱状图 Stacked Bar | 适合“类别内部再拆构成”（如各季度 × 产品线），本需求只有单期一个维度，用不上时间轴 |
| 条形图 Bar Chart | 排名场景可行，但丢失“部分占整体”的直觉 |

**选环形图**（饼图 Pie Chart，类别 4 个，符合 ≤5 类约束），配图例注明金额与百分比。

### 3.3 各渠道转化流失

判断问句：流程流失？→ 漏斗。

| 候选 | 判断依据 |
|---|---|
| **漏斗图 Funnel Chart** | “曝光、点击、注册、付费”式逐步转化流失是漏斗的标准场景，一眼看出哪层最窄 |
| 分组/堆叠柱状图 | 能比渠道大小，但不能表达“逐级流失”的流程语义 |

**选漏斗图**（全渠道汇总，环节：曝光 → 访问 → 留资 → 成交，每层标注转化率与流失率）。但参考文件指出看板三层结构的底部是**明细表（定位原因）**：受众是管理层，追问“哪家渠道流失最严重”时漏斗的汇总视图无法回答 → 因此在底部补**各渠道明细表**（含访问→成交转化率、流失率、环比），柱内 seek 由表格承担。

## 4. KPI 卡规则（layouts.md）

- 每张卡只呈现一个指标，标注环比：`营收 480 万 ▲ 环比 +12.0%`（对齐参考文件格式 `DAU 28,460 +4.7%`）；
- 附注基线：上月 428.4 万、增量 +51.6 万（480 / 1.12 − 1 ≈ 428.4，数据自洽）。

## 5. 交互规则（需求为静态汇报，强度匹配取最低）

- 数据点与漏斗层、环形分段使用 SVG `<title>` 原生悬停提示，零 JS、零打断，符合“轻微事项不重度打扰”的强度匹配原则；
- 无弹窗、无确认等交互，页面可打印（`@media print` 已做投屏/打印适配）。

## 6. 视觉风格

- 业务关系：经营复盘 → 气质正式、克制；
- 浅色底 + 白卡片 + 单一强调蓝（#2563eb），涨跌只用绿/红双色徽标，无科技大屏的深色霓虹（那是态势监控的语言，不适合管理层汇报）；
- 中文界面，金额统一“万元”，数字用 tabular-nums 对齐。

## 7. 数据说明（重要）

用户仅给定两项真实数据：**本月营收 480 万、环比 +12%**。其余数字（12 个月走势、产品线拆分、渠道漏斗、明细表）均为**自洽的演示占位数据**，并保证内部一致：

- 12 个月末点 = 480，前点 = 428.4 → 环比恰为 +12.0%；
- 产品线 192.0 + 134.4 + 96.0 + 57.6 = 480 万（40% / 28% / 20% / 12%）；
- 四个渠道的曝光 / 访问 / 留资 / 成交各列合计 = 漏斗各层（128,600 / 48,200 / 9,680 / 2,910）。

页面已在页脚声明“除已给定指标外为演示占位数据”，替换为真实数据即可投入使用。

## 8. 最终组装规格（Prompt 形式，可直接复用）

> 做一个中文“月度经营报告”单文件页面，受众为管理层，布局采用**上总下分 Summary First**（浅色正式风、白卡片、单强调蓝）。结构三层：
> ① 顶部 KPI 卡：本月营收 480 万元、▲ 环比 +12.0%，旁置“本期要点”三条结论；
> ② 中部三图并排：近 12 个月营收走势用**折线图 Line Chart**（末点高亮 + 悬停可见各月数值）；各产品线营收占比（4 类 ≤5）用**环形图 Donut/Pie Chart**（图例含金额与百分比）；全渠道转化流失用**漏斗图 Funnel Chart**（曝光→访问→留资→成交，每层标注转化率与流失率）；
> ③ 底部**明细表 Detail Table**：按渠道展开曝光/访问/留资/成交、访问→成交转化率、流失率、成交环比，用于定位流失原因。
> 图表以 CSS/SVG 手绘，数据悬停用原生 title 提示，支持打印。
