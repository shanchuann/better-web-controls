# 选型笔记：删除项目确认交互

## 需求转写

原需求："给删除按钮加上合适的确认交互。" 按技能流程，这是**交互反馈规则与时机**类问题 → 查阅 `rules.md` 的"二次确认 — 7 种"一节；同时删除按钮样式与 Modal 四要素参考了 `controls.md`。

**关键判断依据（来自需求原文）**：

- 后台管理场景
- 删除后果：该项目下**所有任务和文件全部清除**
- **不可恢复**（不可逆）

## 候选对比（二次确认 7 种中列出前 3）

| 候选 | 英文 | 适用场景 | 是否合适 |
|---|---|---|---|
| 气泡确认 | Popconfirm | 中等风险、单项操作：删除单条评论、移除一张图片 | 不合适。无法承载"任务+文件全没了"的后果说明，轻量形式与后果严重度不匹配 |
| 弹窗确认 | Modal | 严重后果：删除重要文档 | 接近但不够。蒙版阻断+明确说明过关，但用户仍可能没读提示、条件反射点"确定"，对"影响面大且不可逆"不够 |
| 输入文字确认 | Type to Confirm | 不可逆且影响大：删除仓库、清空数据 | **最合适**。制造额外操作成本，输入完整项目名的过程迫使用户确认目标无误，保证用户读过风险提示 |

参考决策线原文："轻微风险用长按或左滑；中等风险用气泡；严重后果用弹窗；**不可逆且影响大用输入确认或独立确认页**"。核心公式"强度匹配"：轻微事项采用重度确认会干扰用户，严重事项采用轻度确认会导致事故——本例属于最右侧一档。

（独立确认页 Select All to Delete 用于"批量删除+后果逐条说明+全部勾选"，本例是单项目删除且在列表页操作，跳转整页成本过高，不选。）

## 最终选型

**输入文字确认 Type to Confirm + 居中弹窗 Modal 承载**

复合表述："居中的 Modal danger confirm，点击删除项目按钮触发；蒙版阻断页面，要求输入完整项目名称，输入一致后"永久删除"按钮才启用，输入不一致给出提示；点击取消、点蒙版或按 Esc 关闭；内容包含风险说明（任务、文件永久清除且不可恢复）、确认输入框和两个操作按钮。"

## 细节决策

1. **输入"完整项目名"而非固定词 DELETE**：固定词只证明用户读完提示，输入项目名同时证明"针对的就是这个项目"，进一步防选错对象。
2. **未输入成功时禁用按钮**（rules.md 原文："只有输入 DELETE 后按钮才启用"），且视觉上按钮呈半透明禁用态，输入匹配时才点亮。
3. **后果内逐条写明**"全部任务、全部文件与全部成员记录将被永久清除，此操作不可恢复"——二次确认的三项价值：减少误触、说明后果、保留反悔机会（本例不可逆，故不提供 Undo，闭环靠"输入成本"兜底）。
4. **关闭方式**：取消按钮、点蒙版、按 Esc 三种退出，Esc 监听全局。
5. **聚焦与键盘**：打开即聚焦输入框，输入一致后回车可直接执行。
6. **执行后反馈**：用轻提示 Toast（右上角出现数秒自动消失）确认删除完成，并展示项目空状态。

## 验收点

- 输入与项目名一致前，"永久删除"按钮无法点击
- 删除后列表移除该行，Toast 显示结果，全部删完显示空状态
- Esc / 蒙版 / 取消均可关闭弹窗
