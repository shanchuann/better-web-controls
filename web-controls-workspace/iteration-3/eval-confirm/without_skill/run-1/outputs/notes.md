# notes.md — 删除项目确认交互实现说明

## 场景定位
“删除项目”属于**不可恢复的高危操作**（删除会连带清空任务与文件），因此没有使用轻量 toast/气泡确认，而是采用**阻断式模态确认弹窗（alertdialog）+ 输入确认（type-to-confirm）**。

## 布局设计要点
1. **危险语义的视觉表达**
   - 红色警示图标 + 红色实心“确认删除”按钮（与新建等主操作的主色明确区分）。
   - 正文明确说明后果：“删除后所有任务、附件及关联数据将永久清除，不可恢复”。
2. **后果量化展示**
   - 弹窗内列出将删除的具体内容：任务数、附件数、负责人，让用户明确知道自己删了什么。
3. **输入确认替代简单“确定/取消”**
   - 必须手动输入完整项目名称，确认按钮才解除禁用；输入不匹配时给出红色错误提示。
   - 目的：强制用户主动校对目标项目，防止手滑误删。
4. **防机器人式误触的二次保险**
   - 弹窗打开后 1.5 秒内点击确认会被拦截并提示（防止双击删除按钮时，第二击直接命中刚弹出的确认框）。
5. **删除进行中的状态管理**
   - 点击确认后按钮进入 loading（“删除中…”），禁用取消按钮、关闭按钮、遮罩点击、ESC，避免半途状态不一致。
   - 完成后弹出成功 toast（绿色）/ 失败时红色 toast，并在表格中移除该行。
6. **可访问性（a11y）**
   - 使用 `role="alertdialog"` + `aria-modal` + `aria-labelledby`/`aria-describedby`。
   - 打开后焦点移入输入框；Tab 键焦点锁定在弹窗内（focus trap）；关闭后焦点归还给触发按钮；支持 ESC 关闭。
7. **列表页面完整闭环**
   - 页面模拟后台管理列表（侧边栏 + 项目表格），删除按钮为红色 ghost 样式；全部删除后显示“暂无项目”空状态。
   - 删除为演示逻辑（setTimeout 模拟 1.6s 请求），接入真实后端时在 `doDelete()` 中替换为 API 调用即可。
