# 实现说明

"删除项目"属于**不可恢复的高危操作**，确认交互采用了逐级拦截的设计：

## 交互流程
1. **列表内点击"删除项目"** —— 按钮为红色描边样式（默认态克制，不做大面积红色实心），提示危险但可被取消。
2. **弹出模态确认框** —— 展示明确的后果说明：项目名称、将被删除的任务数 / 文件数 / 协作记录，并配警示图标与"不可撤销"文案，避免用户不读后果直接点确认。
3. **输入项目名称确认**（GitHub 式防误触）—— 必须完整输入项目名，"确认删除"按钮才解锁。输入框实时校验并给出正/误反馈，防止批量弹窗式"确认疲劳"。
4. **删除中状态** —— 按钮变为"删除中…"并禁用，遮罩期间禁止点击遮罩/Esc 关闭，避免重复请求；真实场景此期间调用后端接口。
5. **删除完成** —— Toast 提示"项目已删除"（红色，与普通成功提示区分），列表同步移除该行；空列表时显示空状态。

## 可访问性
- `role="dialog"` + `aria-modal` + `aria-labelledby/describedby`，关闭后焦点归还触发按钮。
- Esc 取消、Enter 提交、Tab 焦点圈定在弹窗内。
- Toast 使用 `role="status"` 播报。

## 其他细节
- 点击遮罩空白处 = 取消（不误删）；确认流程中任务已锁定不可中途关闭。
- 单文件、无依赖，双击即可打开演示。
