# 实现说明：删除项目确认交互

## 场景
后台管理的“删除项目”属于不可恢复的破坏性操作，因此不能用简单的单步确认，采用了**强确认（type-to-confirm）**模式。

## 设计要点

1. **危险操作隔离区（Danger Zone）**：删除按钮放在独立红色边框区域，与普通操作分离，让用户明确知道这是危险动作。
2. **点击后弹出确认弹窗**（不用原生 `confirm()`），使用 `role="alertdialog"` + `aria-modal`，明确告知后果。
3. **后果明示**：弹窗列出具体将被删除的内容（128 个任务、342 个文件、协作历史），并强调“不可恢复”，避免用户在做重大决定时信息不足。
4. **输入名称确认**：要求用户手动输入项目名“星辰数据平台”才能激活“永久删除”按钮，防止手滑和误删。
5. **按钮状态**：“永久删除”按钮初始禁用（disabled），输入完全匹配后才启用；确认按钮为红色实心，语义上强化危险。
6. **额外的防误触机制**：
   - 删除执行中显示“正在删除…”加载状态，防止重复点击；
   - Esc / 点击遮罩 / 取消按钮均可关闭弹窗，且删除进行中不允许关闭；
7. **焦点管理**：打开弹窗聚焦到确认输入框，关闭后焦点返还原按钮，Tab 键在弹窗内循环（焦点陷阱），对键盘用户友好。
8. **结果反馈**：删除成功后页面切换为“项目已删除”状态卡，并弹出底部 toast 提示，给予明确闭环。
