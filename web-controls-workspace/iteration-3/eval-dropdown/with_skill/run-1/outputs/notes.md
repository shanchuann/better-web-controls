# 选型笔记：订单管理页 · 指派负责人 + 按负责人筛选

> 依据 `skills/better-web-controls/SKILL.md` 工作流：识别需求类型 → 查阅 `references/controls.md`、`references/rules.md`、`references/tables`（表格一节）、`references/layouts.md` → 列候选与判断依据 → 记录选型 → 按 Prompt 规格实现。

## 一、需求判断（判断先于选择）

用户需求原文："订单管理页面里要选负责人，顺便按负责人筛选订单。"

先判断，需求实际包含 **两个动作、三类内容关系**：

1. **指派动作**：把某条订单分给某个负责人 → "选下拉"默认会被实现成最普通的 `<select>`，需要确定形式与操作规则（来源：controls.md 下拉组件一节，常见误区"说做个下拉会得到最普通的一种"）。
2. **筛选动作**：按负责人过滤订单列表 → 对应 controls.md 表格一节的"**01 表头筛选 Column Filter**"（明确举例适用于"负责人过滤"）。
3. **内容关系**：负责人选项是 **人员列表**——无上下级关系（排除 Cascader）、无明显分组逻辑（Grouped 收益低）、单条订单通常只需一个负责人（排除 Multi-select 用于指派）。

仿照 SKILL.md 完整示例，需要向用户确认的关键判断依据（评测场景无用户，按最合理假设处理并在下文声明）：**选项数量（人员多少）、是否存在层级、是否允许一次选多个负责人**。

## 二、候选对比

### 用于“指派负责人”

| 候选 | 适用场景 | 本场景判断 |
|---|---|---|
| **Select 单选下拉** | 固定少数选项，只能选一个 | ✅ 负责人即团队成员，单选；若人数 ≤ 十几人无搜索需求 |
| **Combobox 可搜索选择框** | 选项多（几十上百人），边搜边选 | 备选：大团队（几十人以上）时更合适；本页按小团队假设，选 Select，但负责人列表集中在顶部一处，后续换 Combobox 改造成本低 |
| **Multi-select 多选下拉** | 一次指派多人/协作人 | ❌ 订单负责人一般只有一个，多选会引入"主负责人/协作人"歧义 |
| Cascader / Grouped Select | 上下级 / 大量分组 | ❌ 人员无层级、无明显分组；Cascader 是 Grouped 不是的上下级（controls.md 提醒） |

### 用于“按负责人筛选订单”

| 候选 | 适用场景 | 本场景判断 |
|---|---|---|
| **顶部筛选 Select（含"全部负责人"，单选）** | 最常见的管理后台过滤方式；回溯、定位、统计都直观 | ✅ 选中后表格即时过滤，显示结果条数 |
| Multi-select 筛选（选中项成标签，可单独移除） | 需要同时看多个负责人的订单做对比 | 备选：本页按"筛选通常只盯一个人"假设选单选，并做**可清空**（× 一键回到全部），覆盖大部分意图 |
| 表头筛选（列头内嵌过滤） | 列多、每列都可能被过滤的重表格 | 备选：本页仅一个高频筛选维度，放顶部更易发现、手机端更好降级 |

### 配套交互（引用 rules.md 确定时机，非新增控件）

- **空状态**：筛选无果 ≠ 没有数据。采用"**筛选无果 No Filter Matches**"规则：保留当前筛选条件显示在结果计数旁（可单独移除的标签 ×），不放大创建按钮，只提示"清除筛选"。
- **结果反馈**：改派成功用 **轻提示 Toast**（右上角出现几秒自动消失），属于"保存成功"级别的 02 等级，不打断操作；不用 Modal。
- **对齐**：金额列 **右对齐 + 等宽数字**（rules.md 数字对齐），订单号等文本左对齐；行内"名称靠左、状态靠右"的端到端对齐感。
- **状态呈现**：订单进度用 **Badge 徽标**（待处理/进行中/已完成），小标签不打断扫读。

## 三、假设声明（评测场景无法向用户确认）

1. 负责人为团队成员约 6 人，无层级、无分组 → 选 **Select 单选下拉**；
2. 订单一次只有一个负责人 → 指派用单选；
3. 筛选按单负责人 + "全部"选项，支持一键清除（若用户反馈"要对比多个负责人"，升级为筛选 Multi-select 并保留现在的单选为默认）；
4. 若实际负责人达数十人，指派控件应升级为 **Combobox 可搜索选择框**（规格见下）。

## 四、最终选型（Prompt 规格，按固定顺序：控件名 → 场景/形式 → 操作规则）

- **筛选下拉**：做一个 **负责人筛选 Select 单选下拉**：位于订单列表顶部，提供"全部负责人"加全部成员选项，只能选一个；选中后列表即时过滤并在计数区显示"已筛选：×××"+ 可单独移除的标签；筛出 0 条时显示空状态——保留筛选标签，提供"清除筛选"入口。
- **行内指派下拉**：每行订单末列放一个 **负责人指派 Select**：触发框显示成员头像缩写与姓名，未分配时显示"分配负责人"占位；点开列出全部成员，选中即更新为该负责人并弹出轻提示 Toast"已指派给 ×××"，右上角数秒自动消失。
- **订单表格**：列含订单号、客户、金额、状态、负责人；金额右对齐等宽数字；状态用 Badge；筛选后计数显示"共 n 条"。

## 五、验收清单（对应交付物 page.html）

- [ ] 顶部筛选 Select：选任意负责人，表格即时过滤、计数同步、出现可移除的筛选标签
- [ ] 筛选无果：空状态文案 + "清除筛选"按钮，点击回到全部
- [ ] 行内指派 Select：可改派任意行，Toast 反馈，表格数据与筛选联动（改派到非当前筛选项时该行随之隐藏/符合当前筛选时出现）
- [ ] Esc / 点击外部可关闭展开的菜单；金额右对齐；中文界面
