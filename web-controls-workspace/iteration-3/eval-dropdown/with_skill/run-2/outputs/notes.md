# 选型笔记：订单管理页面 · 负责人下拉与订单筛选

## 一、需求识别

用户需求原文："订单管理页面里要选负责人，帮我做个下拉选择负责人，顺便按负责人筛选订单。输出一个可以直接打开的完整 HTML 文件（单文件）。"

- 需求类型：**新增控件**（下拉）→ 查阅 `references/controls.md`“下拉组件 — 7种”
- 附带功能：**按负责人筛选订单**（长列表定位器中的"状态筛选"，表格的"表头筛选"场景）→ 查阅 `references/controls.md`“表格”“长列表加载”
- 页面载体：订单管理页面（工具型后台，参考 `references/layouts.md`“工作流实战”三步：核心目标、功能清单、交互细节）

## 二、判断先于选择

"做个下拉"是模糊表述，下拉有 7 种形式。按 `controls.md` 的选型口诀逐一判断：

| 判断问题 | 结论 | 依据 |
|---|---|---|
| 选项是否为日期/时间？ | 否 | 排除 Date Picker |
| 选项是否存在上下级？ | 否 | 负责人是扁平的人员名单，无层级 → 排除 Cascader |
| 选项是否有类别归属？ | 否 | 人数少，无需分组 → 排除 Grouped Select |
| 是否是"默认操作 + 低频操作"？ | 否 | 不是按钮语义 → 排除 Split Button |
| 是否是多列导航面板？ | 否 | 排除 Mega Menu |
| 单选还是多选？ | **单选** | "选负责人"为单点指派/查看语义；且用户说"按负责人筛选"，单选切换即所得 |
| 选项数量是否多到需要搜索？ | 否 | 按常见订单小组规模取 6 人以内 |

## 三、候选对比（2~3 个）

| 候选 | 中文名 | 适用场景 | 本需求适配度 |
|---|---|---|---|
| A | Select 单选下拉 | 固定少量选项中选一个，选择后显示在触发框内，支持清空重选 | ★★★ 负责人少、单选、切换即筛选，最简最准 |
| B | Combobox 可搜索选择框 | 选项多时边搜边选 | ★★ 6 人以内无需搜索，多一层输入成本 |
| C | Multi-select 多选下拉 | 数据过滤场景可同时看多个负责人 | ★★ 用户明确"选负责人"（单数），且未要求"同时看若干人"的对比视角；多选会引入跨人合计的歧义 |

**判断依据补充**：用户未答复关键信息（负责人数量、可否多选）。按规模最小的常见后台理解（人数少、单选），并在笔记中留出升级路径：若负责人超过约 20 人，B 应替换为 Combobox；若需要多人对比，C 替换为 Multi-select。

## 四、最终选型

**做一个负责人 Select 单选下拉**：
- 提供"全部负责人（默认）+ 王强、李娜、周杰、吴敏、赵磊、陈晨、孙悦"七个固定选项，只能选择一个（其中孙悦名下暂无订单，用于演示筛选无果空状态）；
- 选择后姓名显示在触发框内，支持一键清空（回到"全部负责人"，即重选）；
- 每个选项右侧显示各自订单条数，帮助预判筛选结果；
- 交互：点击展开、点选即筛选并收起、点击外部/Esc/Tab 收起；支持键盘 ↑↓ 选择、Enter 确认；
- 边界：筛选结果为空时显示**筛选无果空状态**（当前条件保留在页面，提供"查看全部负责人"一键还原），不留白屏。

**配套的订单列表表现**（按 `controls.md` 表格三问：怎么找、怎么看、怎么操作）：
- 怎么找：顶部负责人 Select 即表头筛选的显性入口，切换实时过滤；
- 怎么看：状态列用徽标 Badge 上色，金额列右对齐、等宽数字、统一两位小数（对齐五式中的数字对齐）；表头下方展示"共 X 条 / 筛选后 Y 条"；
- 怎么操作：演示数据规模小（十几条）无需分页，不引入 Pagination 以免过度设计。

## 五、Prompt（按固定顺序组装）

> 做一个负责人 Select 单选下拉：提供"全部负责人 + 王强、李娜、周杰、吴敏、赵磊、陈晨、孙悦"七个固定选项，只能选择一个，选择后显示在触发框内，支持一键清空重选；点击展开下拉面板，点选即按负责人过滤下方订单表格并收起，点击面板外部、按 Esc 或 Tab 也收起，键盘 ↑↓ 移动、Enter 确认；每个选项右侧显示该负责人的订单条数；筛选无匹配时，保留当前筛选条件并显示"筛选无果"空状态与"查看全部负责人"还原按钮。订单表格中状态用徽标展示，金额右对齐使用等宽数字并保留两位小数。
