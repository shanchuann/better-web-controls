# 选型笔记：CRM 客户列表的两种空状态

需求原文："CRM 系统里客户列表在两种情况下会空：新用户刚注册还没有客户；以及搜索/筛选后没有匹配结果。"

## 一、需求转写（判断先于选择）

本需求属于工作流中的“交互反馈规则”类，查阅 `references/rules.md` 的“空状态 — 5种”一节与“对齐 — 5种”一节，并参照 `references/controls.md`（按钮 / 搜索输入 / Select / 表格）与 `references/layouts.md`（工具型页面结构）。

核心判断：**空状态不应统一做成"提示加按钮"，先说明页面为什么为空，原因不同，引导不同。**（rules.md 总结口诀：创建给入口，搜索改关键词，筛选改条件，失败可重试，完成给反馈）

| # | 需求场景 | 为什么空（归因） | 应对原则 | 选定控件 |
|---|---|---|---|---|
| 1 | 新注册账号，客户列表无数据 | 首次使用首轮使用 First-use | 提供创建与导入入口，帮助用户开始 | 首次使用空状态 FIRST-USE EMPTY STATE |
| 2a | 输入关键词后无匹配 | 搜索无结果 NO SEARCH RESULTS | 保留原关键词；修改建议放在搜索框旁；不添加大按钮 | 搜索无结果空状态 NO-SEARCH-RESULTS EMPTY STATE |
| 2b | 选择筛选条件后无匹配 | 筛选无结果 NO FILTER MATCHES | 当前条件保留在页面，可逐个移除（"点击上方标签×，减少一个条件"） | 筛选无结果空状态 NO-FILTER-MATCHES EMPTY STATE + 可移除条件标签 REMOVABLE FILTER CHIP |

## 二、候选对比与选型理由

### 情况一：新账号无客户（3 个候选）

| 候选 | 适用场景 | 本次是否采用 | 理由 |
|---|---|---|---|
| ① 首次使用空状态：居中插画 + 一句引导 + “新建客户”实心主按钮 + “导入客户”线状次按钮 | 任务型列表页，首个动作明确（录入 / 批量导入） | ✅ 采用 | 符合 rules.md "创建给入口"；按钮层级符合 controls.md 三步公式（全页仅一个面状主按钮） |
| ② 分步引导 Onboarding Checklist（待办清单式：1 添加客户 2 导入数据 3 邀请同事） | 多角色协作、配置项多的系统 | ❌ | 单一"客户资料"任务拆三步过重；操作链变长，反而稀释主行动 |
| ③ 纯占位提示："暂无数据" 一行灰字 | 系统工具内部视图 | ❌ | 违反不留空白页原则，未给任何下一步入口 |

### 情况二：搜索/筛选后无匹配（3 个候选）

| 候选 | 适用场景 | 本次是否采用 | 理由 |
|---|---|---|---|
| ① 按归因拆分：搜索无结果与筛选无结果各一套（①a 关键词保留 + 建议贴搜索框；①b 条件标签可逐个移除） | 搜索与筛选可能单独或同时生效 | ✅ 采用 | 两类原因的解法不同（"搜索改关键词，筛选改条件"），拆开才能给出正确下一步 |
| ② 合并为单一"无匹配"空状态 + 一个"清除全部"按钮 | 条件只有一种来源的简单列表 | ❌ | 混淆归因：搜索无果不应全清（关键词可能只需微调），筛选无果"一键全清"会破坏用户想保留的剩余条件 |
| ③ 不做独立空状态，仅在表头显示一行小字提示 | 数据密度高、打扰敏感的界面 | ❌ | 无图标无引导，与"不留空白页、给出路"原则不符 |

### 关键判断依据（原需求已给出，无需再次确认）

- 空状态的两种成因已由用户明确定义 → 不存在归因歧义。
- 假设（已按合理默认处理，写在实现里）：① 中文界面；② 搜索关键词与筛选条件可同时生效，两者叠加无结果时优先展示"筛选无结果"（提示中补充说明关键词仍生效）；③ 搜索无结果的修改建议以小字辅助条贴在搜索框旁，同时空状态区不出现面状大按钮（遵守"不添加大按钮"）。

## 三、最终选型（按固定顺序组装的 Prompt 规格）

**情况一 · 首次使用 FIRST-USE EMPTY STATE**
- 场景与形式：新账号客户列表无数据；居中引导——插画、短标题、说明、按钮沿同一轴线居中（rules.md 对齐：空状态引导居中）；不留空白页。
- 入口规则：提供两个入口——“新建客户”面状实心主按钮（全页唯一），打开居中弹窗 Modal 录入客户（弹窗四要素：类型居中、按钮触发、取消/确认/Esc 关闭、表单内容含必填标记“客户端名称*”）；“导入客户”线状次按钮，批量导入。
- 边界情况：录入成功后空状态自然消失并回到列表；操作反馈用右上角轻提示 Toast，数秒自动消失。

**情况二a · 搜索无结果 NO-SEARCH-RESULTS EMPTY STATE**
- 场景与形式：有关键词但无匹配；空状态内保留并回显原关键词；建议（换全名/缩短关键词/检查错别字）以胶囊提示贴在搜索框旁，空状态区给出同类建议。
- 操作规则：不添加大按钮，仅提供"清空关键词""手动录入这条客户"两个文字按钮 TEXT BUTTON；清空后回到全部列表。

**情况二b · 筛选无结果 NO-FILTER-MATCHES EMPTY STATE**
- 场景与形式：筛选组合无匹配；所选条件以可移除条件标签 REMOVABLE CHIP 的形式保留在列表上方，每个标签带 ×，可逐个移除。
- 操作规则：空状态文案明确指引"点击上方标签的 ×，逐个减少条件"；提供"移除全部筛选条件"文字按钮；如果关键词同时生效，附注说明关键词仍在过滤。
- 边界情况：移除任一条件后视图即时刷新；全部条件移除后回到完整列表。

配套控件（均符合 references/controls.md 规格）：搜索文本框（含清空按钮）、来源/状态 Select 单选下拉、客户状态徽标 Badge、轻提示 Toast、居中 Modal、单一实心主按钮 + 线状/文字按钮的页面层级。

## 四、实现与自查

- 单文件 `page.html`：内嵌 CSS/JS，无外部依赖，中文界面，双击即可打开。
- 演示路径（页面底部 demo-note 也有说明）：打开即为“首次使用”→ 点击"导入客户"填充 8 条示例 → 输入 `xyz` 出现“搜索无结果”→ 选择 `官网 + 已成交`（该组合在示例数据中无匹配）出现“筛选无结果”→ 逐个点 × 移除条件验证即时刷新。
- 移动端降级（rules.md）：窄屏隐藏次要列（电话、最近跟进），工具栏换行，空状态内边距收窄。
- 无障碍：图标按钮带 aria-label，Esc 关闭弹窗，必填错误就地提示。
- 自查：JS 语法校验通过（Node `new Function` 全脚本解析）；所有 `$()` 引用均能对应到页面 id；script 标签与花括号配对平衡；内部文案一律经 textContent 渲染（无 innerHTML 注入用户输入）。

## 五、明确不做（附依据）

- “加载失败 Loading Error”“全部完成 All Done”两类空状态未实现：需求只要求前两种，页面无异步请求，不存在失败态。
- 未做暗色模式：需求未要求，避免过度交付。
