# notes.md — CRM 客户列表双空状态选型笔记

依据：`better-web-controls/SKILL.md` 工作流 + `references/rules.md`“空状态 —— 5 种：原因不同，引导不同”。

## 1. 需求识别

用户给出的两类"为空"场景，对应 rules.md 空状态清单中的两种不同**原因**，不能统一做成"提示 + 按钮"：

| 用户原话 | 对应类型 | rules.md 规则 |
|---|---|---|
| "新用户刚注册还没有客户" | 首次使用 First-use | 提供创建与导入入口，帮助用户开始 |
| "搜索/筛选后没有匹配结果" | 搜索无果 No Search Results / 筛选无果 No Filter Matches | 搜索：保留原关键词，修改建议放搜索框旁，不加大按钮；筛选：当前条件保留在页面，可逐个移除 |

这是交互反馈规则问题（何时给什么引导），当前目录下已查阅 `rules.md`；涉及搜索框与筛选标签的控件描述参考了 `controls.md` 中的 Multi-select“选中项以标签展示，可单独移除”句式。

## 2. 候选对比（每个场景 2–3 个候选）

### 场景一：新用户首次使用

- **候选 A：创建 + 导入双入口 + 三步引导** —— 新用户最需要的不是解释"为空"，而是给出可立即行动的两条路径（逐条建 / 批量导），配合简短步骤说明降低起步门槛。适合 CRM 这类录入即产生价值的工具。
- **候选 B：单一"新建客户"大按钮** —— 最简单，但丢掉了"批量导入"这个老用户迁入的主路径，引导不完整。
- **候选 C：教学视频/功能介绍插画** —— 适合功能复杂难懂的产品；客户列表概念直白，添加教学内容会拖慢用户行动。

**采用 A**：新建 + 导入两个并列入口，下方一行三条步骤指引。

### 场景二：搜索无果

- **候选 A：保留关键词 + 建议放搜索框旁 + 小链接清空** —— rules.md 原文方案。用户意图明确（找某个具体客户），最有效的帮助是帮他改关键词，而不是引导离开搜索。
- **候选 B："新建客户"大按钮** —— 搜索无果时推荐创建，会在用户明确想"找"时误导他去"建"，且万一客户存在只是没搜到，会造成重复建档。
- **候选 C：展示"您可能想找"的相似客户** —— 需要模糊匹配算法，单文件演示不具备；规则上属增强项，非必需。

**采用 A**：关键词保留在输入框并出现在标题中；建议浮层出现在搜索框正下方（更短关键词/检查错别字）；仅提供"清空搜索关键词"文字链接，不加大按钮。

### 场景三：筛选无果

- **候选 A：条件以标签形式保留在工具栏，逐个可移除（×）+ 清除全部** —— rules.md 原文方案。用户能通过"删一个条件试一次"快速定位是哪个条件过严，列表随删随匹配。
- **候选 B：全部按钮清空重来** —— 操作成本最低但破坏上下文，用户不知道是哪个条件组合导致为空，下次还会踩坑。
- **候选 C：在空状态面板上重复罗列条件** —— 与工具栏信息重复，且引导动作与上方标签脱节。

**采用 A**：条件标签保留在面板顶部（状态：已成交 × / 标签：流失风险 ×），空状态文案直接指向上方"点击条件标签的 ×，减少一个条件"，另有"清除全部筛选"兜底。

## 3. 判断依据

1. **原因先于形式**：三种为空原因（无数据 / 搜索无果 / 筛选无果）各自对应不同的引导动作——"创建给入口，搜索改关键词，筛选改条件"。页面按原因分流，而非统一"图标 + 文案 + 按钮三件套"。
2. **搜索与筛选同时无果时的优先级**：判定为筛选无果视图。理由：筛选标签可被用户逐个移除，是两种出口中信息保留最完整的一种；此时关键词仍保留在输入框内，用户清掉任一条件即可看到搜索结果，双重引导兼备。
3. **强度匹配**：搜索无果不给大按钮（用户意图是找，不是建）；首用场景才给主按钮（行动意图成立）。
4. **条件可见性**：筛选条件激活时，标签行始终显示在工具栏下方，即使结果不为空也可见——保证"结果 → 条件"的因果始终可读。
5. **搜索建议的位置**：rules.md 要求"修改建议放在搜索框旁"，因此即时提示放在搜索框正下方（浮层），空状态正文只保留关键词回显与通性建议。

## 4. 最终选型理由（Prompt 规格）

- **空状态一：首次使用空状态 First-use Empty State。** 用于新注册、客户列表无任何数据时：插画 + 标题"还没有客户" + 一句价值说明；并列"＋新建客户""导入客户"两个入口按钮；下方三条起步步骤（新建 → 导入 → 指派跟进）。边界情况：一旦存在任何客户（哪怕被搜索/筛选隐藏），本状态不再出现。
- **空状态二：搜索无果空状态 No Search Results Empty State。** 用于搜索关键词无匹配时：关键词保留在输入框与标题中；修改建议即时显示在搜索框正下方；仅提供"清空搜索关键词"文字链接，不放置大按钮。
- **空状态三：筛选无果空状态 No Filter Matches Empty State。** 用于筛选条件无匹配时：被选条件以可移除标签（带 ×）保留在页面上方，每移除一个条件列表立即重新匹配；空状态文案引导"点击上方条件标签的 ×，减少一个条件"，并提供"清除全部筛选"文字链接。

三类状态互斥：无数据（首用）→ 搜索无果 → 筛选无果 → 正常表格，由 JS 按上述优先级实时判定渲染。
