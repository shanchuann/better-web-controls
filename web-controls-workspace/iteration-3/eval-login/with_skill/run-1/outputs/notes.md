# 选型笔记 —— SaaS 登录页（品牌色：陶橙）

需求原文："帮我们 SaaS 产品做个登录页，要高级一点，品牌色是陶橙色。输出一个可以直接打开的完整 HTML 文件（单文件）。"

依据 `SKILL.md` 工作流：先查 `references/layouts.md`（登录页 5 种）确定结构与布局，再按 `references/rules.md`（表单校验时机、提示等级、等待体验）与 `references/controls.md`（按钮、表单输入控件）确定控件规格。

---

## 一、布局候选对比（layouts.md · 登录页 5 种）

| 候选 | 名称 | 适用的 SaaS 场景 | 问题/判断依据 |
|---|---|---|---|
| A | 居中卡片式 Centered Card | 内部工具、功能优先的 B 端产品 | 稳妥但品牌表达弱，"高级感"主要靠留白，难以承载陶橙品牌色与叙事 |
| B | **Split Screen 左右分屏式** | **品牌展示与登录并存，SaaS 官网 → 登录的延续** | 左侧讲品牌（价值主张+社证），右侧放表单，可大面积使用品牌色且不干扰填写 |
| C | 沉浸背景式 Immersive Background | 传播型、活动型产品 | 表单直接叠在 陶橙→金色 渐变底上；陶橙饱和度高，文字与输入框对比度需要深遮罩兜底，"高级感"容易滑向"海报感"，且表单可读性风险最高 |

判断依据（来自需求原文 + 参考文件）：
1. 用户明确给了品牌色"陶橙"→ 说明希望品牌被感知，而非纯功能页；
2. "SaaS 产品"→ 目标用户是 B 端决策链少、高频登录的团队用户，需要专业感而非喧闹感；
3. "高级一点"→ 按 rules.md 设计术语拆解为可执行项：**留白、栅格、克制配色**，而非堆渐变毛玻璃；
4. 未见"多角色""分步验证"诉求 → 排除 Role-based Tabs 与 Step-by-step（只有邮箱密码两项，字段 ≤ 4，按 controls.md 不应拆步）。

**最终选型：B · Split Screen 左右分屏式**——"做 6:4 左右分屏，左边讲品牌，右边放无卡片表单；移动端折叠单栏布局。"理由：唯一能同时满足"品牌色被充分使用"与"表单可读性、填写效率"两端的方案；左右分区天然形成留白与栅格秩序，陶橙大面积只在左区，右侧冷处理（暖白底 + 灰棕中性色），主色被"克制"下来反而更高级。

## 二、控件级选型（controls.md）

| 内容 | 选型 | 理由 |
|---|---|---|
| 登录按钮 | **全宽面状按钮 SOLID FULL-WIDTH BUTTON**（圆角 14px，陶橙实心） | 表单内唯一主操作，实心且全页仅这一个主色按钮；宽度撑满容器，移动端表单标准形态。悬停加深 + 轻上浮微交互 |
| 忘记密码 / 申请试用 | **文字按钮 TEXT BUTTON** | 不与主操作争夺注意力 |
| 三方登录 | **线状按钮 OUTLINE BUTTON** × 2 | 次操作，仅描边无底色 |
| 邮箱 / 密码 | **Text Field**，Label 在输入框上方 + 必填标记 + Helper Text（如"至少 8 位"） | rules.md 表单体验检查点：不依赖 placeholder 说明字段含义 |
| 密码可见切换 | IconButton（眼睛图标，aria-pressed，键盘可聚焦） | 登录高频需求，纯说明性图标按钮 |
| 三方图标 | 线性 stroke 图标，与输入框图标统一语言 | rules.md 风格一致性（图标语言：线性、细线） |

## 三、交互规则选型（rules.md）

| 场景 | 选型 | 规则表述 |
|---|---|---|
| 校验时机 | **失焦校验 Blur + 提交校验 Submit 组合**，出错后即时重校验 | "邮箱失焦时校验格式；提交时统一校验必填项并定位到第一个错误项；错误提示显示在输入框下方" |
| 错误反馈 | 行内错误提示（红边框 + 输入框下方文案 + 逐字段 shake 微动效） | 说明"哪里错了、应该怎么改"（如"密码至少 8 位，请检查是否输入完整"） |
| 登录等待 | **不确定进度 Indeterminate** → 按钮内 **循环同步 spinner** | 接口等待时长未知，不编造百分比；按钮置灰防重复提交 |
| 登录成功 | **轻提示 Toast**（右上角，3 秒自动消失）+ 按钮短暂绿色成功态 | 成功率高、后果轻微，强度与后果匹配 |
| 切换/提交防抖 | submitting 状态锁 | 避免双击重复提交 |
| 可访问性 | Label 关联、role="alert"、aria-invalid、focus-visible、触控目标 ≥ 44px | 移动端降级逐项检查 |

## 四、视觉规格（"高级一点"的落地参数）

- 布局：6:4 网格分屏；左侧品牌区上下留白 ≥ 56px，右侧表单最大宽 396px 居中
- 主色：陶橙 `#E0693C`，深变体 `#C4552F`（hover），浅底 `#FDF1EA`（辅助提示底）
- 中性色：暖白底 `#FAF7F3`、主文字暖近黑 `#241B14`、次文字 `#6E6259`、分隔线 `#E8DFD8` —— 全站暖色系中性色，与陶橙同温，避免"橙色 + 纯灰"的脏感
- 左区渐变：158° `#E8794A → #C24A26`，加白色高光与暗角 radial，配细线圆环 / 光晕圆点缀，阴影换虚线圆以避免噪点
- 层级：主按钮实心唯一，其余全部线状/文字按钮；卡片仅左侧 quote 使用，右侧无卡片（留白建立层级）

## 五、移动端降级（rules.md 逐项检查）

- 820–880px 折叠为单栏：品牌区收为顶部品牌条（标题保留、描述与社证隐藏），表单放下
- 输入框/按钮高度 48–50px，命中区域 ≥ 44px；触屏无 hover，先经 hover 的元素均带无 hover 可用的默认态
- 邮箱输入 `inputmode="email"`、`autocomplete` 触发对应键盘与填充

## 六、信息不足时的假设（如需可调整）

1. 未提供品牌名 → 使用占位品牌"澄云"及中文文案，替换 Logo/名称即可
2. 未提供三方登录方式 → 使用"企业微信 / 钉钉扫码"占位
3. 未要求多角色/验证码 → 按单角色、无分步实现；若需 SMS 验证码可改为分步登录式
4. "记住我"默认勾选行为、登录跳转目标（demo 停留在页内）为演示逻辑
