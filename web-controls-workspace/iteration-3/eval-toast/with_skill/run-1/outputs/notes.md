# 选型笔记：保存成功反馈

## 需求转写

原文："设置页面里用户点保存后要有个反馈，保存成功就行，不要打断用户操作。"

关键信息拆解：

- 场景：设置页面，表单类操作
- 触发：用户点击"保存"按钮
- 反馈内容：保存成功（正向结果，轻量信息）
- 约束：**不打断用户操作**——排除一切阻断式反馈（弹窗、蒙版、需要点击确认的东西）

依据技能"提示消息 — 7个等级，从轻到重"表（rules.md），打断程度应与信息重要程度匹配；保存成功属于"轻量、正向、无需用户处理后消失"的信息。

## 候选对比（引用 rules.md 七等级表中的相关项）

| 候选 | 级别 | 特点 | 是否适用 |
|---|---|---|---|
| 角标提示 BADGE | 01 | 数字标在图标右上角，表达未读/待办数量 | 不适用——保存成功不是数量信息 |
| **轻提示 TOAST** | 02 | 右上角出现数秒自动消失，不打断操作 | **适用**——rules.md 中"何时用"一栏即举例"保存成功" |
| 带操作的轻提示 SNACKBAR | 03 | Toast 附带可立即执行的按钮（撤销/重试） | 备选——仅当保存后需要"撤销/查看"动作时升级为它；本次只需告知结果，不附带操作 |
| 消息中心通知 NOTIFICATION | 05 | 发到消息中心留档，随时回看 | 不适用——保存成功无需留档，用户也不需要回看 |
| 警告提示 ALERT | 06 | 固定在内容区，处理前不消失 | 不适用——这是失败/风险用的重提示，会打断用户 |
| 弹窗确认 Modal | — | 蒙版阻断页面，要求明确选择 | 不适用——直接违反"不打断"约束 |

## 判断依据

1. **信息强度**：保存成功是轻微、正向信息，按"强度匹配"原则（打断程度与后果重要性匹配）应选低打断级别（01–03 中选取）。
2. **是否需要用户动作**：用户明确说"不要打断"。BADGE 表达不了结果反馈；NOTIFICATION / ALERT 都会引入额外查看成本；只有 Toast（02）是"出现数秒自动消失"。
3. **是否附带操作**：保存成功不需要"撤销"或"重试"入口，因此无需升级到 SNACKBAR（03）。若未来有"保存后可撤销"需求，再升级即可。

## 最终选型

**轻提示 Toast（TOAST）**，右上角出现、约 3 秒自动消失、无按钮、不阻断任何操作。

对应完整 Prompt（按技能固定顺序：控件名 + 形式 + 操作规则）：

> 做一个轻提示 Toast：保存设置成功后，页面右上角滑入一条带对勾图标的成功提示"设置已保存"，停留约 3 秒后自动淡出；不带按钮，不需要用户确认，不遮挡、不阻断页面上的其他操作；连续保存时出现的新提示在原位置刷新或叠放。

## 实现落点（page.html）

- 设置页使用中等偏简的表单布局：字段标签 + 必填标记 + 辅助说明，按"基础设置 / 通知与外观 / 账户安全"逻辑分组（rules.md 表单整体体验检查点），落在设置页语境里。
- 保存按钮为页面唯一主操作，采用面状按钮（controls.md：主操作、视觉权重最高）。
- Toast 定位 `position: fixed` 右上角，不入文档流、不推挤内容；动画为滑入 + 淡出；容器设 `aria-live="polite"` 供读屏器播报；重复点击保存时刷新/重置计时器，避免多条提示堆叠。
