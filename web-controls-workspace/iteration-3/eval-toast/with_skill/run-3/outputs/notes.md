# 选型笔记：保存成功反馈

## 需求分析

用户需求原文："设置页面里用户点保存后要有个反馈，保存成功就行，不要打断用户操作。"

- 需求类型：交互反馈（提示消息），查阅 `references/rules.md` 的“提示消息 — 7 个等级”表。
- 关键判断：信息为"保存成功"（低优先级成功确认），后果轻微（设置保存可随时再改）；用户明确要求"不打断操作"。

## 候选对比

| 候选 | 级别 | 是否满足"不打断" | 适用场景 |
|---|---|---|---|
| 轻提示 TOAST | 02 | 满足：右上角出现，数秒自动消失，不遮挡内容区 | 保存成功、复制成功、已收藏等轻量确认 |
| 带操作的轻提示 SNACKBAR | 03 | 满足，但附带操作按钮 | 删除后撤销、断线重试等需要立即动作的场景 |
| 消息中心通知 NOTIFICATION | 05 | 不满足意图：留档可回看，为异步任务结果设计 | 导出完成、批量任务结果 |
| 警告提示 ALERT | 06 | 不满足：固定在内容区、处理前不消失 | 权限不足、异常、风险 |

倒查一个反例：如果这里用弹窗 Modal（用户需点"确定"才能继续），就违反了"强度匹配"公式——轻微事项采用重度确认会干扰用户，与需求"不要打断用户操作"直接冲突。

## 判断依据

1. 保存成功属于典型的低优先级成功确认，无需用户任何后续操作。
2. 用户明确给出"不打断"约束，指向 02 级（TOAST）而非 06 级（ALERT）或弹窗。
3. 不需要附带操作按钮（没有"撤销保存"或"查看详情"的诉求），因此 03 级 SNACKBAR 过度设计。

## 最终选型

**轻提示 Toast（右上角出现，数秒自动消失）** —— 与 rules.md 行业惯例一致。

实现要点（单文件 HTML，page.html）：

- 位置：固定右上角，与页面内容区隔离，不遮挡正在编辑的表单。
- 消失规则：约 3 秒自动消失；悬停暂停（防止用户正在阅读时消失）；提供"×"手动关闭兜底。
- 视觉：白底卡片 + 左缘 3px 成功色边线 + 对勾图标，成功信息一目了然；底部细条动画表现剩余时间。
- 堆叠：多条提示自上而下排列，可并存不互相覆盖。
- 无障碍：容器 `role="status"` + `aria-live="polite"`，屏幕阅读器播报但不抢占焦点（polite 而非 assertive，符合"不打断"）。
- 保存过程：按钮短暂显示"保存中…"（模拟请求），完成后弹 Toast 打消成功确认；用户可立即继续操作。
- 细节：`prefers-reduced-motion` 时关闭动画；中文界面；双击可直接打开。
